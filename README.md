# 官网与管理工作台

沿用 E1「清新」配色，使用 React + TypeScript + Vite。两个独立入口共用基础样式与课程概要，**没有修改微信小程序的业务代码或用户缓存**。

## 打开与运行

需要 Node.js 22.16 或以上：

```powershell
npm ci --ignore-scripts
npm run dev
```

- 官网：`http://127.0.0.1:5173/`
- 管理后台：`http://127.0.0.1:5173/admin/`
- 生产构建：`npm run build`；本地检查构建结果：`npm run preview`，端口为 `4173`。
- 两个入口都要通过本地服务打开，不能双击 HTML。部署时保留构建目录中的 `admin/index.html` 与 `assets`；后台采用哈希路由，详情页刷新无需额外重写规则。

当前开发机没有独立 Node/npm，依赖已安装。可以用已存在的微信开发者工具内置运行时启动预览：

```powershell
Set-Location 'D:\WxProgram\medical\code\web'
$env:ELECTRON_RUN_AS_NODE = '1'
& 'D:\WxProgram\微信web开发者工具\微信开发者工具.exe' '.\node_modules\vite\bin\vite.js' preview --host 127.0.0.1 --port 4173 --strictPort | Out-String
```

不要重复启动同一端口；正式开发环境仍建议安装独立 Node.js。

## GitHub Actions + GitHub Pages

已准备 [部署工作流](./.github/workflows/deploy-pages.yml)。**工作流按本目录作为独立 Git 仓库根目录设计**，不要将原始客户资料、小程序、缓存或真实业务数据一起提交。当前还没有关联远程仓库，也没有完成线上发布。

1. 在 GitHub 选定一个允许使用 Pages 的仓库，将本 Web 工程放在仓库根目录，保留锁文件；默认分支采用 `main`。
2. 仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。
3. 推送到 `main` 后自动执行，也可在 **Actions → Deploy website and workspace → Run workflow** 手动触发。
4. 工作流会安装锁定依赖、运行测试、类型检查、构建两个入口、校验静态资源，再仅发布 `dist`。无需把访问令牌写进代码或配置个人 Token。
5. 成功后的地址在工作流的 `github-pages` 环境中查看。一般为官网 `https://<owner>.github.io/<repo>/`，后台在同一地址下的 `admin/`。

构建从 Pages 配置读取根路径，支持仓库子路径和自定义域名。后台内部使用哈希路由，详情页刷新仍可打开；官网与后台互跳也会保留仓库路径。

**发布边界：** 按公开可访问的评审站点对待，后台的身份选择不是访问控制。不能上传真实患者资料、密钥或尚未获准公开的内容。Pages 只托管静态前端，不提供后端、多人数据共享或正式账号服务。真正上线的管理后台需要独立认证、服务端权限与受保护的数据服务。

本地检查仓库子路径（检查后移除环境变量，再重新构建可恢复本地根路径）：

```powershell
$env:PAGES_BASE_PATH = '/medical-web/'
npm run build
npm run check:build
npm run preview
# 验证地址：http://127.0.0.1:4173/medical-web/
```

治疗师 B 只能看到分配给自己的参与者。列表为空、无权访问、存储失败和版本冲突会明确提示，不以成功提示掩盖失败。

## 数据与后端边界

- **仅供内部评审，全部参与者和记录为虚构，不要填写真实个人或健康信息。** 身份选择不是正式登录，本地身份范围也不是生产安全控制。
- 后台保存到浏览器 `localStorage` 的 `medical:web:workspace:v1`；刷新可恢复，浏览器禁用存储时会报错。读取损坏记录不会自动重置。
- [业务接口](./src/admin/services/contracts.ts) → [实现绑定](./src/admin/services/index.ts) → [本地实现](./src/admin/services/local.ts)。未来以 HTTP 实现替换绑定；正式请求失败不能自动切回本地数据。
- 写入有版本校验并记录操作历史；重置是独立的本机工具，不要求生产 API 支持。
- 官网通过独立的 [公开内容接口](./src/site/api.ts) 获取内容概要，不加载后台参与者、答卷或日志。
- **后台、官网和微信小程序暂不实时同步。** 分组、反馈与发布只改变后台本机记录，不会开通微信课程、发送消息或更新官网。
- 人工复核只演示记录流程，不代表完成真实联络、专业评估或风险处置。当前没有即时咨询、自动报警或真实临床服务。
- 官网不收集报名资料；正式二维码、机构、联系方式、完整视频、隐私文件与服务时段仍待确认。没有虚构这些材料，当前也未公开部署。

```powershell

```

测试使用隔离内存数据，不会清理浏览器记录。测试中的主动存储失败日志和 Node TypeScript 转换实验性提示不代表测试失败。

浏览器验收需覆盖：身份进入 → 分组 → 反馈草稿/提交 → 人工复核 → 课程审核发布 → 日志；官网目录展开、内容弹窗、参与说明、问答与移动导航。至少检查 320、393、768、1440px 宽度；表格可在自身容器内横向滚动，页面本身不应溢出。弹窗支持 Esc、关闭按钮和键盘操作。
